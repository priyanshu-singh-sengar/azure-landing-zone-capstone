# Azure Bastion Module (`modules/bastion`) — Detailed Explanation

## 1. Overview & Purpose

The `bastion` module provisions a fully managed **Azure Bastion PaaS host** and its dedicated Public IP address within `AzureBastionSubnet`.

Azure Bastion delivers secure, agentless administrative access (RDP and SSH) directly to private VMs across all peered spoke VNets via TLS/HTTPS port 443. This completely eliminates the need to attach public IP addresses to virtual machines or maintain legacy, high-maintenance jumpboxes.

---

## 2. Resources Created

1. **`azurerm_public_ip.bastion_pip`**:
   - Static, Standard SKU Public IP.
   - Used by Microsoft's Bastion gateway to accept incoming browser/CLI connections.
2. **`azurerm_bastion_host.bastion`**:
   - Deployed with configurable SKU (`Basic` or `Standard`).
   - In `Standard` SKU, supports **native client tunneling** (`tunneling_enabled = true`), enabling developers to use local tools (OpenSSH, VS Code Remote SSH, native RDP clients) through `az network bastion tunnel`.

---

## 3. Inputs & Outputs

### Key Inputs (`variables.tf`)
- `name`: Name of the Bastion resource.
- `sku`: `"Standard"` (default) or `"Basic"`.
- `bastion_subnet_id`: Resource ID of the `AzureBastionSubnet` in Hub VNet.
- `tunneling_enabled`: Enables native client SSH/RDP tunneling (Standard SKU only).
- `file_copy_enabled`: Enables browser-based file upload/download to VMs.

### Outputs (`outputs.tf`)
- `id`: Resource ID of the Bastion host.
- `public_ip`: Public IP address of the Bastion ingress endpoint.
- `dns_name`: Autogenerated FQDN for Bastion management connections.
